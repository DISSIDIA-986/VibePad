## Problem Statement

在 macOS 上躺床使用 Xbox 蓝牙手柄，控制豆包 IME 的语音 Toggle（Right Ctrl 按一次开始、再按一次结束），同时保持 Ghostty 终端输入焦点。需要可配置按钮映射、Enter/⌘Enter 发送、Backspace/⌘Z 撤销、可选摇杆鼠标（死区+灵敏度）、后台常驻、低延迟。非目标：长按模式、通用游戏映射、GUI、跨平台。

## What Makes This Cool

一键 Toggle 语音、眼睛不用离开天花板也能打字发消息。手柄变成「躺着用的豆包遥控器」，Ghostty 始终是文字落点。

## Constraints

| 约束 | 说明 |
|------|------|
| 平台 | macOS GoldenGate Public Beta 主目标；API 不变则 best-effort macOS 14+ |
| 手柄 | Xbox 蓝牙，GameController 框架 |
| 豆包 | Toggle 模式，热键 = Right Ctrl |
| 终端 | Ghostty 保持焦点 |
| 形态 | 独立 daemon + YAML，无 GUI |
| 权限 | Accessibility（CGEvent 注入） |

## Premises（已确认）

1. 豆包 Toggle = 每次 Right Ctrl **短按**切换开/关（非长按）。
2. 转写文本**直接进 Ghostty 光标**（豆包 IME 管道写入前台 app）。
3. 仅需 macOS + Xbox 蓝牙；不需要 GUI。
4. CGEvent 注入需要 Accessibility 权限。
5. **最高风险**：合成 Right Ctrl 是否被豆包 IME 接受 — 必须在真机 Spike 验证后才能宣称完成。

## Landscape（Phase 2.75）

**Layer 1 — 业界共识**：macOS 下手柄→键盘/鼠标的标准栈是 GameController（读输入）+ CGEvent（写事件）+ Accessibility 权限。代表项目：ControllerKeys (xbox-controller-mapper)、macpad、ControlDeck。

**Layer 2 — 可复用 daemon**：padjutsu / gamacros 提供 YAML + SDL 轮询 + `tap`/`keystroke`/`mouse_move`，但 gamacros 文档示例是 **hold-to-talk（长按 rcmd）**，与 Toggle 需求相反；padjutsu 的 `tap: rctrl` 可能够用但未针对 IME Toggle 验证。

**Layer 3 — Eureka**：VibePad 不需要重造 HID/蓝牙。差异只在 **Toggle 语义**（单次 tap Right Ctrl）、Ghostty/豆包 tuned defaults、以及低延迟轮询。参考 macpad 的教训：合成事件后需 `flags = []` 避免 modifier 泄漏导致 ctrl+click。

## Approaches Considered

### Approach A: Padjutsu 零代码 YAML
用现成 `padjutsud` + `gc_profile.yaml`，A 键 `tap: rctrl`。今晚可试。无专用 toggle 状态机；IME 若需 FlagsChanged 序列则失败。

### Approach B: VibePad 独立 Swift daemon（**已选**）
Swift Package，`vibepad` CLI + launchd。GameController 输入、CGEvent 输出、YAML 配置、内置 Ghostty/豆包 默认 profile。Toggle 与 deadzone 完全可控。

### Approach C: Fork padjutsu 加 `toggle` action
复用 Rust/SDL 引擎。维护成本高，Toggle 语义仍需自证。

## Recommended Approach

**Approach B — VibePad Swift daemon**

理由：你已选定独立 daemon；Toggle 是核心差异化，必须自有 `InputSimulator` 层控制 Right Ctrl 的 down/up 时序与 `CGEventSource`；padjutsu/macpad 仅作参考实现，不作运行时依赖。

## Architecture

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ Xbox BT         │────▶│ GameController   │────▶│ MappingEngine   │
│ (GCController)  │     │ poll ~500-1000Hz │     │ YAML rules      │
└─────────────────┘     └──────────────────┘     └────────┬────────┘
                                                          │
                        ┌──────────────────┐              ▼
                        │ CGEvent (.cghid) │◀── InputSimulator
                        │ keyboard + mouse │     MouseEngine (stick)
                        └────────┬─────────┘
                                 ▼
                        Ghostty (focus) + 豆包 IME
```

### 核心模块

| 模块 | 职责 |
|------|------|
| `ConfigLoader` | 加载 `~/Library/Application Support/VibePad/config.yaml`；v1 改配置需 `launchctl kickstart` 重启 |
| `MappingEngine` | 按钮/chord → Action；边沿 debounce 50ms（见下） |
| `AppMonitor` | 读 frontmost bundle ID，匹配 profile |
| `InputSimulator` | `tapKey(.rightControl)`、`tapCombo("cmd+enter")` 等 |
| `MouseEngine` | 左/右 stick：`deadzone`、`gamma`、`max_speed_px_s`、`precision_button` |
| `DaemonLifecycle` | launchd `KeepAlive`、Accessibility 检测、日志、TCC 失败 exit 1 |

### Profile Resolution

1. 读 frontmost app bundle ID（`NSWorkspace.shared.frontmostApplication`）。
2. 在 `rules.*.apps` 中找第一个匹配项。
3. **无匹配 → no-op**（按钮/摇杆均忽略）。v1 不提供 global fallback profile。
4. 多 profile 同时匹配时按 YAML 声明顺序取第一个。

### Controller Lifecycle

| 事件 | 行为 |
|------|------|
| 无手柄 | idle，500ms 轮询重连 |
| 断连 | 日志 + 继续轮询 |
| 重连 | 绑定第一个 `GCExtendedGamepad` Xbox 控制器 |
| 多手柄 | 仅用第一个，忽略其余 |
| sleep/wake | 重新枚举 GCController + 重检 Accessibility |

### Permission / TCC

- 启动时检查 Accessibility；拒绝 → stderr 指引 + **exit 1**（launchd 会重试）。
- 运行中权限被撤销 → 日志 + 停止 posting，等待重启。
- `vibepad doctor` 打印：权限状态、手柄连接、frontmost app、config 校验。
- GoldenGate 上若 CGEvent 仍失败，再查 Input Monitoring（Spike 时一并验证）。

### Action 类型（YAML v1）

| Action | 行为 |
|--------|------|
| `tap` | keydown + keyup，无 repeat（**Toggle 语音用此**） |
| `combo` | 修饰键序列，如 `cmd+enter`、`cmd+z` |

v1 **不含** `hold`（与 Toggle 非目标一致）、`click`（需求未提，v2 再加）。

### Debounce

边沿触发：同一按钮 `tap`/`combo` 执行后 **50ms 内忽略后续 press**。不影响 keydown/keyup 成对发送。

### 未映射输入

D-pad、Guide、RT、右摇杆（若未配置 stick mode）→ **忽略**，无默认行为。

### 默认映射（可覆盖）

### Config Schema（v1）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | int | yes | 固定 `1` |
| `poll_hz` | int | no | 默认 `500`；可选 `1000`（更高 CPU） |
| `rules.<name>.apps` | [string] | yes | bundle ID 列表 |
| `rules.<name>.buttons.<btn>` | action | no | `a`,`b`,`x`,`y`,`lb`,`rb`,`lt`,`rt`,`dpad_*`,`start`,`back` |
| `buttons.*.tap` | key | | `rctrl`,`enter`,`backspace`,… |
| `buttons.*.combo` | string | | `cmd+enter`, `cmd+z`, `ctrl+c` |
| `sticks.left/right.mode` | enum | no | v1 仅 `mouse_move` |
| `sticks.*.deadzone` | float 0-1 | no | 默认 `0.18` |
| `sticks.*.gamma` | float | no | 默认 `2.0` |
| `sticks.*.max_speed_px_s` | int | no | 默认 `2400` |

Key 别名：`rctrl` = Right Control (0x3E)；`rcmd`,`lctrl`,`lcmd`,`option`,`shift` 同理。

### MouseEngine 公式

```
normalized = max(0, (abs(axis) - deadzone) / (1 - deadzone))
speed_px_s = max_speed_px_s * pow(normalized, gamma) * sign(axis)
delta_px = speed_px_s / poll_hz
if precision_button held: delta_px *= precision_multiplier
```

单元测试覆盖：axis=0、axis=deadzone、axis=1、precision 乘数。

### Threading

- 专用 `DispatchQueue`（`.userInteractive`）跑 poll timer + CGEvent post。
- 不在 main runloop 上 post 事件。
- AppMonitor bundle 查询每 200ms 缓存一次，避免每 tick 调 NSWorkspace。

```yaml
version: 1
poll_hz: 500

# Ghostty bundle: com.mitchellh.ghostty
rules:
  ghostty:
    apps: [com.mitchellh.ghostty]
    buttons:
      a: { tap: rctrl }        # 豆包语音 Toggle
      b: { tap: enter }        # 发送
      x: { combo: cmd+enter }  # 强制发送
      y: { tap: backspace }    # 删一字
      lb: { combo: cmd+z }     # 撤销
    sticks:
      left:
        mode: mouse_move
        deadzone: 0.18
        max_speed_px_s: 2400
        gamma: 2.0
        precision_button: lt
        precision_multiplier: 0.25
```

### Toggle 实现细节

豆包 Toggle = 每次物理 Right Ctrl 短按切换状态。VibePad **不维护本地录音状态**（避免与 IME 状态漂移）；每次按钮边沿触发：

```swift
// virtualKey 0x3E = Right Control
postKey(.rightControl, keyDown: true)
postKey(.rightControl, keyDown: false)
// 两次 post 之间间隔 1-5ms；flags 清空防泄漏
```

若 Spike 失败（IME 忽略合成键），fallback 顺序（**仍在 Spike 阶段，非 v1 范围**）：
1. `CGEventSource(stateID: .hidSystemState)` vs `.combinedSessionState`
2. `post(tap: .cgAnnotatedSessionEventTap)` vs `.cghidEventTap`

若 1–2 均失败 → **暂停 v1**，产品决策：换 Approach A/C 或调研 IOHID（独立 spike，不进 v1 scope）。

### 延迟预算

| 阶段 | 目标 |
|------|------|
| GC poll → action | < 4ms @ 500Hz |
| CGEvent post | < 2ms |
| 端到端按钮→键事件 | < 20ms p99 |
